# 研究会のお知らせを載せる手順（ブラウザだけでできます）

パソコンに何かを入れる必要はありません。ブラウザで GitHub を開いて、決まった形のファイルを 1 つ作るだけです。
所要時間は、慣れれば 5 分ほどです。

学級通信にたとえると、次のような流れです。

- **ひな形（`_template.md`）** ＝ 学級通信の「型紙」。毎回これを写して書きます。
- **保存（コミット）** ＝ 書いた原稿を職員室の棚に入れること。
- **自動の組み立て（Actions）** ＝ 係が原稿を印刷して配ってくれること。誤字ではなく「書式の誤り」があると、係が配らずに戻してくれます。

---

## 用意するもの

- GitHub のアカウント（会の Organization「shingaiken」に招待されていること）
- 研究会の情報：名称、日時、形式（オンライン・対面）、会場、参加費、Peatix の URL、紹介文

---

## 手順 1　ひな形を写す

1. ブラウザで会のリポジトリ（`shingaiken.github.io`）を開きます。
2. 画面の一覧から `src` → `content` → `events` の順にフォルダを開きます。
3. `_template.md` をクリックします。
4. 右上の「Copy raw file」（四角が 2 つ重なった形のボタン）を押します。中身がすべてコピーされます。

## 手順 2　新しいファイルを作る

1. 一つ前の画面（`events` フォルダ）に戻ります。
2. 右上の「Add file」→「Create new file」を押します。
3. 上の「Name your file...」の欄に、ファイル名を半角で入れます。

   **ファイル名の決まり：`開催日-英字の短い名前.md`**

   | よい例 | だめな例（理由） |
   |---|---|
   | `2027-02-27-open-lesson-2.md` | `2027-2-27-open-lesson.md`（月・日は 2 けた） |
   | `2027-05-15-online-seminar.md` | `2027-05-15-セミナー.md`（日本語は使えない） |
   | | `2027-05-15 seminar.md`（空白は使えない） |

   このファイル名が、そのままページの URL になります。決めたら変えないでください。

4. 下の大きな欄に、手順 1 でコピーした中身を貼り付けます（Ctrl＋V、Mac は ⌘＋V）。

## 手順 3　中身を書き換える

ひな形には、項目ごとに説明が書いてあります（`#` で始まる行は説明なので、残しても消してもかまいません）。

- 【必須】と書いてある項目は、必ず書きます。
- 【任意】の項目で使わないものは、その行ごと消します。
- 日時は `'2027-02-27T10:00:00+09:00'` の形で、最後の `+09:00`（日本時間）を忘れずに付け、全体を半角の `' '` で囲みます。どちらかが欠けるとエラーになります（時刻が 9 時間ずれたまま公開されるのを防ぐためです）。
- 名称・副題・説明（`title`・`subtitle`・`summary`）などの文は、いつも全体を半角の `' '` で囲みます。
  - 囲まないと、文の中の半角のコロン（`: `）や半角の `#` でエラーになったり、文が途中で切れたりします。
  - `' '` で囲んだ文の中で半角の `'` を使うとき（例 Let's）は、`''` と 2 つ重ねて書きます（例 `'Let''s try'`）。
  - 全角の「」や：は、そのまま使ってかまいません。
- 対面・ハイブリッドの研究会では、会場の住所（`venueAddress`）も必須です。
- 参加費は数字だけを半角で書きます（「円」やカンマは付けません）。
- 2 つ目の `---` より下が、ページの本文です。見出しは行の先頭に `## ` を付けます。

## 手順 4　保存する

1. 右上の緑のボタン「Commit changes...」を押します。
2. 「Commit message」に、何をしたかを短く書きます（例：「2月の公開授業研究会を追加」）。
3. 「Commit directly to the main branch」を選んだまま、「Commit changes」を押します。

## 手順 5　公開されたか確かめる

1. 画面上の「Actions」タブを押します。
2. いちばん上の「Deploy to GitHub Pages」の印を見ます。数分で変わります。
   - 黄色い丸：組み立て中です。待ちます。
   - **緑のチェック**：公開されました。サイトを開いて確かめてください（反映まで 1〜2 分かかることがあります）。
   - **赤い ×**：書き方に誤りがあります。下の「うまくいかないとき」を見てください。
3. 開催日までは「次回の研究会」に、開催日を過ぎると翌日の 0 時すぎに自動でトップの「研究会の記録」と研究会一覧の「過去の研究会」に移ります。

---

## 開催後：開催報告を書き足す

新しいファイルは作りません。同じファイルに書き足します。

1. `src/content/events/` の中の、その研究会のファイルを開きます。
2. 右上の鉛筆の形のボタン（Edit this file）を押します。
3. いちばん最後に、次のように書き足します。

   ```
   ## 開催報告

   （当日の内容や参加者数などを書きます）
   ```

4. 手順 4・5 と同じように保存して、確かめます。

## 写真を載せるとき

- 載せてよいのは、**児童の顔が写っていない写真**か、**学校から掲載の許諾を得た写真**だけです。迷ったら載せないでください。
- 写真は `events` フォルダで「Add file」→「Upload files」から入れます。ファイル名は半角英数字にします（例：`2027-02-27-open-lesson-2-1.jpg`）。
- 研究会のファイルの `images:` に、写真ごとに次の 3 つを書きます。1 つでも欠けると公開されません。写真は、研究会のページの本文の下に並んで表示されます。

  ```
  images:
    - src: ./2027-02-27-open-lesson-2-1.jpg
      alt: 授業の板書のようす
      consent: true
  ```

  - `src`：写真のファイル名（前に `./` を付けます）
  - `alt`：写真の説明（読み上げソフトなどで使われます）
  - `consent: true`：掲載の許諾を確かめた、という印

---

## うまくいかないとき

- **赤い × が出た**：× をクリックし、さらに「build」→「Build」を開くと、誤りの内容が英語で出ています。多いのは次のものです。
  - `summary` が短すぎる・長すぎる（20〜200 字）
  - `start` の書き方が違う（`+09:00` がない、全体を `' '` で囲んでいない、月・日が 1 けた）
  - ファイル名の形が違う（月・日が 1 けた、日本語や空白を含む、先頭の日付が `start` の日付と違う）
  - `format` や `kind` に、決められた言葉以外を書いた
  - 対面・ハイブリッドなのに `venueAddress`（住所）がない
  - 文を `' '` で囲んでいないため、文の中の半角の `: ` や `#` でエラーになった。または `' '` で囲んだ文の中に半角の `'` がある（`''` と 2 つ重ねる）

  ファイルを開き直して直し、もう一度保存すれば大丈夫です。**誤りがある間は、サイトは前の状態のまま**で、まちがったページが公開されることはありません。
- **緑なのにサイトに出てこない**：ファイル名が `_` で始まっていないか、`.md` で終わっているかを確かめてください。ブラウザの再読み込みも試してください。
- **どうしても分からない**：保存した内容はいつでも元に戻せます。サイト担当者に、ファイル名とエラーの画面を送って相談してください。
